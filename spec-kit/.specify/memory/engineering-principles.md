# Princípios de Engenharia

- KISS: prefira a solução mais simples que cumpra o requisito.
- YAGNI: não implemente capacidade não solicitada.
- DRY: remova duplicação real, não abstraia código prematuramente.
- SOLID: use somente onde houver benefício concreto.
- Baixo acoplamento: domínio não conhece detalhes de transporte.
- Testabilidade: regras importantes devem ser exercitáveis sem navegador quando possível.
- Observabilidade: decisões de performance devem ter métricas.
- Segurança por padrão: negar por padrão é preferível a conceder capacidade implicitamente.
- Falhas explícitas: erros não podem ser mascarados para “fazer funcionar”.
